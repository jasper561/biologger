Deployment

Start arms the logger and writes that state to flash, so a power glitch resumes logging instead of ending the deployment. While deployed it sleeps between samples and opens a Bluetooth window for about 10 seconds every 2.5 minutes — if Connect does not find it at once, leave the dialog open and wait for the next window.

Adaptive sampling
Sample fast while something is happening, slowly when nothing is. Requires both a still accelerometer and stable temperatures before slowing down, and returns to the fast rate on the first sample that is not quiet.
Calibrate the activity threshold before trusting this. The default 40 mg is a guess, not a measurement. Log your animal at rest and during normal activity with adaptive off, plot accel_sd_mg, then set the threshold above the resting band and well below the active band. The slow_mode column records which rate produced every sample, so the decision stays auditable after the fact.

Use a phone personal hotspot or a plain WPA2 network. WPA2-Enterprise (username and password) and captive-portal networks will not work. Credentials are saved on the logger, so later sessions can just use Saved network.

Firmware Update over WiFi
This page is loaded over https, so the browser will block an upload to the logger's plain-http address. Either open this file locally (file://) or use the logger's own update page: open update page.
  1. Connect the logger to WiFi in the card above.
  2. Arduino IDE: Sketch → Export Compiled Binary, then find the .ino.bin in the sketch's build folder.
  3. Pick it below and upload. The board verifies the image before switching to it and reboots on success — a bad or truncated upload is rejected and the current firmware keeps running.
